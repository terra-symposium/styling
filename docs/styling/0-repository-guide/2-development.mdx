This guide is for contributors working on `@terra-symposium/styling`. The repository builds the publishable library from `src/` and the Styling reference site from `docs/styling/` and `site/`.

Agent workflows: [Styling](https://github.com/Terra-Symposium/styling/blob/development/.agents/skills/ui/SKILL.md) and [UI variants](https://github.com/Terra-Symposium/styling/blob/development/.agents/skills/ui-variants/SKILL.md).

## Repository map

```text
src/
  assets/fonts/       Font files and licenses
  components/ui/      Shared React primitives and variant contracts
  documents/          Editable document templates
  lib/                Hue utilities, types, and Tailwind preset
  styles/             Tokens and source stylesheets
docs/styling/          Markdown, MDX, and interactive documentation examples
site/src/pages/       Astro routes, including the generated component detail route
scripts/              Build, Docs, and TypeScript reference generation
tests/                Component and library checks
```

The package root exports hue utilities. The `./ui` entry point exports shared components, variants, and types. Build output and package declarations are generated in `dist/`.

For the route from component source through generated API data, authored examples, usage prose, and the live reference page, see [Component pipeline](/styling/0-repository-guide/3-component-pipeline/).

## Requirements

- Node.js compatible with the Astro toolchain in the lockfile.
- pnpm, using the version declared by the project or CI.
- Network access to install dependencies from the npm registry.

## Install and build

```sh
pnpm install --frozen-lockfile
pnpm run build
```

`pnpm run build` rebuilds `dist/`, generates TypeScript references, emits type declarations and CSS, and compiles the package styles.

## Run and build the Docs site

```sh
pnpm run docs
pnpm run docs:build
```

`pnpm run docs` builds the package, then starts the local Astro Docs site. `pnpm run docs:build` builds the package, checks the documentation, and writes the static site to `dist/docs/`.

Add guide pages as Markdown or MDX files under `docs/styling/<section>/`. The Docs site discovers those files, derives routes from their paths, and builds nested navigation automatically. Frontmatter supplies page titles, descriptions, and optional order. The component catalog and interactive demos live beside the Colouring pages; a dynamic route serves component references generated from the public TypeScript API.

## Checks

```sh
pnpm run docs:check
pnpm run test
git diff --check
```

`docs:check` validates documentation TypeScript and demo coverage. `test` builds the package and runs the component and library checks. Run the narrowest relevant checks after changing shared component or hue behavior, and use `git diff --check` before sending a change.

## Contributions

- Read the owning component, its public prop types, shared variant contracts, and relevant checks before changing behavior.
- Keep color and treatment choices in the typed component `variant` prop. Keep layout geometry in the component or Docs stylesheet.
- Use static class strings so Tailwind can discover them during CSS generation.
- Preserve accessible names, keyboard behavior, visible focus, disabled and invalid states, and responsive layouts.
- Update the relevant guide when a public export, supported variant, default, or setup step changes.
- Run the package build and relevant checks; visually inspect the Docs route when presentation changes.

The repository UI workflow is documented in the [Styling agent skill](https://github.com/Terra-Symposium/styling/blob/development/.agents/skills/ui/SKILL.md).

## Versioning

This package uses Changesets. Create a changeset for a releasable package change, then update package versions and changelogs:

```sh
pnpm changeset
pnpm version-packages
```

Review the generated changeset and version updates before publishing. The package is configured for public registry access. Publishing is a separate release action.
